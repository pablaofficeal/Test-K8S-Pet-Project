# Мессенджер (MVP)

Чат со сквозным шифрованием. Сервер это «тупой курьер»: хранит публичные ключи и непрозрачные зашифрованные конверты, открытого текста не видит никогда.

## Части

| Часть | Где | Роль |
|-------|-----|------|
| Курьер | `messenger/` (Go) | каталог публичных ключей, зашифрованная копия ключа, доставка конвертов, список чатов, счётчики непрочитанного |
| Криптография | `frontend/src/lib/messenger/crypto/` (TypeScript) | схема ниже, в браузере |
| Эталон | `mm/crypto_tui.py` (Python) | прототип, с которым сверяется TypeScript |
| Интерфейс | `frontend/src/pages/messenger/` | чаты, настройка ключа, словари |

## Схема (как в прототипе)

1. У каждого пользователя долгоживущая пара X25519. Публичный ключ (`key_id = sha256(public)[:32]`) регистрируется на сервере.
2. Для каждого сообщения берутся случайные salt (32 Б) и nonce (16 Б). `HKDF-SHA256(X25519(приватный, публичный собеседника), salt, info)` даёт 64 байта: ключ маски и ключ MAC. В `info` входят тип и версия конверта, алгоритм, id ключей отправителя и получателя и хэши обоих словарей.
3. Каждый символ превращается в группу из 4-7 токенов: один настоящий (индекс символа со сдвигом из потока HMAC-SHA256, токен из словаря 1 или 2) спрятан среди шума. Словари открытые, защищает текст ключевой сдвиг.
4. В конверте поля `type, version, algorithm, alphabet_hash, alphabet_hash2, sender_key_id, recipient_key_id, salt, nonce, ciphertext, auth_tag`. `auth_tag` это HMAC-SHA256 по метаданным и шифртексту (encrypt-then-MAC), проверяется до любой расшифровки.

Ключевое расписание симметрично, поэтому отправитель может перечитать свои отправленные сообщения (`role: 'sender'`).

## API курьера (`/main/api/v1/messenger/...`, везде нужен JWT)

| Метод | Путь | Назначение |
|-------|------|-----------|
| PUT | `put/my/key` | зарегистрировать или сменить публичный ключ |
| GET | `get/my/key` | свой ключ и зашифрованная копия |
| PUT | `put/my/key/backup` | сохранить непрозрачную копию (PBKDF2 и AES-GCM, делается в браузере) |
| GET | `get/user/key/:uuid` | публичный ключ другого пользователя |
| GET | `search/users?q=` | поиск пользователей по началу имени |
| POST | `send/message` | сохранить конверт для получателя (проверяются форма и id ключей, содержимое прочитать нельзя) |
| GET | `get/my/messages?peer=&after=&limit=` | переписка; `after` это курсор по id для опроса |
| GET | `get/my/conversations` | чаты со счётчиками непрочитанного |
| PATCH | `mark/my/messages/read` | отметить сообщения собеседника прочитанными |
| DELETE | `delete/my/message/:id` | отправитель удаляет сообщение у всех |

## Известные ограничения MVP

- Приватный ключ лежит в `localStorage` браузера. XSS, расширения или другой человек с доступом к профилю могут его прочитать. В нативных приложениях нужно системное хранилище ключей.
- Нет forward secrecy (статические ключи), защиты от повторов и сверки отпечатков.
- Из-за слоя шума сообщения растут примерно в 40 раз, лимит конверта 1 МБ.
- Отправить можно только символы из словарей.
- Доставка опросом (3 с в чате, 5 с для списка). WebSocket-хаб планируется вместе с модулем todo.
- Схема самописная и не проходила разбор криптографом.
